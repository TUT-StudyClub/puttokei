# Review PR

## 手順

1. PR 番号または URL を決める。無ければ現在ブランチの PR を対象にする
2. `gh pr view` でメタ情報を取得する
3. `gh pr diff` で差分を読む
4. 次の観点でレビューする
   - 設計とアーキテクチャ
   - バグとロジック
   - テスト不足
   - セキュリティ
   - 可読性と命名
5. 指摘を日本語でまとめる
6. 投稿はユーザーが明示したときだけ行う

## 出力ルール

- まず指摘事項を優先度順に出す
- 可能ならファイルパスと行番号を付ける
- なぜ問題かと、どう直すかの方向性をセットで書く
- 指摘が無い場合も「無し」と明言し、残るリスクやテスト不足を添える

## 注意

- 根拠のない称賛だけで終わらせない
- 差分が大きい場合は高リスク箇所から先に見る
